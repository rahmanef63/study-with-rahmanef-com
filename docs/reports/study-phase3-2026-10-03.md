# Study phase 3 — admin, analytics, richtext and MCP

Scope accepted on 2026-10-03. The earlier [phase 1 and phase 2 change ledger](study-phase1-phase2-2026-10-03.md) remains the record for reader scroll/sticky navigation, comments, duplicate back buttons and cleanup.

## Changes

- The account menu consumes the persisted platform-admin flag. `/admin` now has a guarded overview and coherent navigation to learning statistics, Visitors, community moderation and admin MCP. Community owners do not automatically become platform administrators. No account roles were changed.
- Learning analytics covers users, communities, memberships, courses, lessons, skills, quizzes, active learners, member-day reads, completions, badges, attempts/pass rate, new comments and memberships. WIB daily trends, 7/30/90-day periods, searchable community/course/material/quiz comparisons, sorting and CSV export expose bounded-read completeness. Anonymous requests and nonadmins are denied at the backend.
- Visitors covers page views, ephemeral browser sessions, CTA clicks, referrers, UTM source/campaign, paths, screen classes, browser, OS, language, timezone, local-hour trends, country and approximate city. The 7/30-day query discloses dropped events and scan limits, includes recent masked sessions and supports CSV. Sessions are not unique people. New tracking has no retrospective history.
- First-party ingestion respects DNT/GPC, excludes private/admin/profile/reader paths, removes raw query strings, and never stores raw IP/account identity. A runtime-only service secret protects the Convex HTTP sink; bounded proxy/global budgets, short-lived rate buckets and scheduled 30-day retention control collection.
- Local DB-IP City Lite September 2026 supplies country/city estimates from a verified proxy address. Language/timezone never substitute location; missing data stays unknown. DB-IP attribution appears beside the dashboard. No paid geolocation service or foreign IP API is used.
- Shared Markdown rendering fixes escaped placeholders, nested inline/list formatting, multiline paragraphs, table pipes, balanced links, fenced code and exact code copying. The editor's Markdown roundtrip preserves long fences and code blank lines. Existing authored content stays intact.
- YouTube URL/directive/safe iframe sources render through one responsive privacy-enhanced embed with validated video IDs/start offsets and fetched title/channel/thumbnail metadata. Metadata lookup is fixed-host, bounded, cached and time-limited; missing metadata preserves a usable video/watch link. Unsafe HTML/URLs remain inert.
- Separate account-owned user/admin MCP tokens can be issued once, expired and revoked. Seventeen capabilities reuse guarded application handlers behind two stable discovery/execution tools. See [setup and capability contract](../STUDY-MCP.md).

Managed host file: `/home/rahman/.local/share/study-with-rahmanef-com/geo/ip-city.mmdb`, root:root 0444 inside root:root 0555 directory. Dokploy binds the directory at `/data/geo`; `ANALYTICS_GEO_CITY_DB=/data/geo/ip-city.mmdb`. Dokploy 0.30.8 cannot express a read-only bind in its mount schema: this is a **permission-protected bind**, whose nonroot uid 1001 cannot write or chmod the root-owned file. Verify this boundary after deployment. Updating the pinned data requires hash/licence/date review, an atomic host replacement and an application restart because the reader caches its first result; update the dashboard dataset label too.

Proxy contract: Next has no published service port; Traefik web/websecure keep default untrusted-forwarding behavior with no trustedIPs/insecure/notAppend override. Use the last observed X-Forwarded-For hop. Only a last hop in the reviewed official Cloudflare networks can authorize CF-Connecting-IP; direct origin peers ignore CF headers. Workers, synthetic/private/reserved addresses are unknown. Never reuse this adapter if Next becomes directly exposed or forwarding policy changes without re-verifying the transport boundary.

Rollback: retain the privately saved pre-release Dokploy configuration and `study-with-rahmanef-com-inpwce:rollback-phase3-20261003` image. Restore the earlier source/runtime revision and environment, redeploy, and verify health/source. Schema additions are optional/additive; preserve collected data and credentials. Reverting frontend does not require deleting tables or changing existing auth keys. Temporary verification tokens must be revoked through their owner before concluding the release.
